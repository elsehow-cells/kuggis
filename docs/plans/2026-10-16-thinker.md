# The Thinker

Status: built 2026-10-16 (kuggis PR "The Thinker", four commits: the door,
the wall, any agent, retire), awaiting review and `kuggis think --setup`.
Builds on [the cells plan](2026-10-15-cells.md), which defines cells, doors
and the trusted cell. This plan is the Thinker's half of trusted, pulled
forward.

## What I want

I open the Thinker on my laptop and tell it what I want done. It knows my
vault. It finds the right cell, starts the work there, watches it, and steers
it. I attach to a session when I feel like it. I hear about it when something
actually needs me, and otherwise I don't. I don't review PRs.

The Thinker has BigBrain and nothing else of mine. Nothing leaves the room
except through a door, and nothing leaves the cells through the Thinker.

## Where it stands

Built:

- The room (`kuggis think`): the `thinker` user, my home at 700, a
  root-owned launcher, token login with no connectors, Claude Code with no
  shell and a hook that lets WebFetch open only URLs it was handed.
- Briefs: the Thinker writes `outbox/<name>.md`; `kuggis dispatch` shows it
  to me, I press `d`, the session starts on the VM with the brief as its
  first message.
- Cells in the CLI (#19–#22): `kuggis <cell> <session>`, cell files, the
  development contract, in-cell review and merge (live on airo, #18).

Missing:

- The vault. BigBrain's MCP door is merged (elsehow/BigBrain#307) but not
  released; `mcp.json` in the room is empty.
- Sight. The Thinker gets `inbox/status.md` and PR diffs, written only when I
  run kuggis. It can't see what a session is doing.
- The wall is Claude Code. The user and the home are OS-level; the network
  wall is `--tools` and a hook. Swap the agent and the wall goes with it.
- The gate is a web page I don't want.

## The wall is the OS

The OS is the protection; the agent's own settings are a second layer, never
the wall. Then the agent in the room can be any agent, shell included.

1. **User and files** (done): the `thinker` user, standard and hidden; my home
   at 700; the room root-owned.
2. **Network**: macOS's process sandbox (`sandbox-exec`, a kernel wall, no
   root needed at run time), applied by the root-owned launcher to the agent
   and everything it starts: no network at all except outbound TCP on
   loopback to a local allow-list proxy and to BigBrain's door. Unix sockets
   count as network on purpose, so even a name lookup is refused (the
   resolver is reached over one, and a hostname carries data out). Built and
   checked 2026-10-16: direct connection, DNS, UDP, listening and another
   loopback port all refused by the kernel. The launcher sets `HTTPS_PROXY`;
   an agent that ignores it simply can't connect, which is the right
   failure. The proxy (`think/proxy.py`, run by `kuggis watch` as me) tunnels
   CONNECT to the model APIs in `think/hosts` and nothing else; TLS runs end
   to end, so it sees hostnames, never content. Every allowed host passes the
   trusted-cell test: only I can read what's sent there. (A per-uid pf rule
   was the first idea; the sandbox is stronger and simpler: pf can't see the
   system resolver's lookups, and needs a boot daemon and edits to the
   system firewall config.)
3. **Web**: not from the agent. Search and fetch are door tools (below), so
   the URL rule lives outside the room and is the same for every agent.
4. **Check**: `kuggis think --check` grows a network half, run from inside the
   room: reach the open internet, resolve a name, connect to any other local
   port, send a packet with a raw socket. All must fail.

The Claude launcher keeps `--restricted` and no shell. Codex and pi get the
same user, home, proxy and door, and whatever exits they have are turned off
by name (Codex's own sandbox can't nest inside the wall, so it runs without
one). None of that is what holds; the wall is. The WebFetch hook is gone:
with the wall up it guarded a tool the room no longer has, and pages come
through the door with a rule the agent can't influence.

## The door: one kuggis tool in the room

A root-owned MCP server in `/opt/kuggis-thinker`, speaking stdio to the
agent, touching only the Thinker's inbox and outbox. `kuggis watch`, as my
login user, carries: it refreshes the inbox on a timer and acts on the
outbox. kuggis still writes only the inbox and reads only the outbox; nothing
of mine listens on a socket the room can reach. (BigBrain's door does, but it
was built for untrusted clients and has its own token.)

| Tool | Does | Rule |
|---|---|---|
| `cells` | the cells, their projects, their VMs | read |
| `sessions` | every session: state, needs-me flag, last screen of output | read |
| `brief` | a brief into a new or running session (one tool: `session.sh deliver` already does both) | yours |
| `outcome` | what happened to a brief: waiting, sent, edited, rejected | read |
| `search` | a web search | open |
| `fetch` | a page | open if the URL came back from a `search` in this session; yours otherwise |

`brief` writes a brief and returns its hash with "waiting for Nick".
The Thinker says so in the chat and gets on with something else; `outcome`
tells it when I've acted. The old hand-written brief still works; the tool is
the convenient path, not a new permission.

`fetch`'s rule replaces the hook's provenance check with one the agent can't
influence: the carrier remembers which URLs it returned. A link I want it to
read, I hand to kuggis (`kuggis url <link>`), not to the agent, because the
carrier can't see my chat.

## The gate is kuggis, not the agent

A brief waits for me. kuggis shows it to me and I press `d`. It is rendered
by kuggis in my terminal, never by the agent: an agent can show me one thing
and write another, and with a shell it can skip the tool and write the file.
So an "approve in the chat" gate is not a gate. This is the same read as
today's dispatch, made immediate.

`kuggis think` becomes a small tmux cockpit: the chat in one window, the home
screen one window over (`C-b n`), the watcher in a third; the bar turns orange
when something waits, a brief or a fetch. One key. My phone pings. The
decision lands in `outcome`. Without tmux the chat runs alone and the watcher
behind it.

Driving a session this way costs me a `d` per follow-up. That is the price
until the closed-world check from the cells plan graduates and briefs into
public cells go on their own. The pressure to widen the door "for this
session" is exactly the pressure the cells plan says to resist; the relief is
the check, not a wider door.

## When something needs me

The VM hooks already flag a permission prompt, a question, and `needs-you
blocked|done`. The carrier puts the flags in the inbox; `sessions` shows them
with the session's last screen. The Thinker tells me in the chat, with what
the session is asking, and proposes an answer; if I agree, it sends a
follow-up, which I dispatch. The ntfy ping stays. No separate screen.

## Merges

In-cell, by the development contract (#22): CI and a reviewer session on the
VM post the checks, the author merges. Onboard bigbrain-dev and
merrillfront-dev. The Thinker does not review PRs: a PR diff is text written
on an internet-connected VM, and reading it into the room is how the Thinker
gets steered; the cells plan's reviewer-in-cell is the right place.

The one repo I still read is kuggis itself. It runs as my login user with
everything, and it is the thing that holds the walls. Its PRs stay mine.

## Sight is a cost I accept

The Thinker now reads sessions' screens, which is VM-written text entering
the room. The cells plan kept the Thinker out of the review loop for that
reason. The difference: a steered Thinker can't leak (the OS closes every
exit) and can't act (briefs wait for me). The worst it can do is write a bad
brief or a bad drop, and I read briefs. Drops into the vault are attributed
and untrusted. So sight is bounded, and the Thinker gets it.

## What goes

- `kuggis web`: the cockpit and the chat replace it.
- `kuggis prs` and the Thinker's background reviews (#11), once bigbrain-dev
  merges in-cell.
- The fetch hook: redundant once the wall is up and fetch goes through the
  door, so deleted rather than kept as a second layer.
- The home screen keeps the session list and becomes the gate pane.

## Any agent

`kuggis think --agent claude|codex|pi`. One launcher per agent in the room,
root-owned, all sharing the user, home, proxy, door and system prompt; each
with its own credential, kept in the room, to an account that is mine. The
check runs the same against each. Codex: `web_search` off, no apps, plugins,
browser or computer use, hooks off. pi: its tools are an allowlist already.
Workers on the VMs already run all three (#21); the brief's `agent` field
picks the worker.

## What this changes in the cells plan

- Trusted's egress wall lands now, on the room, as trusted's first piece;
  BigBrain and the household data join the cell later as planned.
- The dashboard section: the web page goes. What it was for survives: red
  means needs-me, and a door holding something is a row with how long.
- The Thinker reads session screens (above). It still doesn't review PRs.
- Words in runs downhill, unchanged: briefs are yours until the closed-world
  check graduates.

## Order of work

1. **The door and the cockpit.** The MCP server, `kuggis watch`, the inbox
   format (`cells`, `sessions` with flags and screens, `outcome`), `start` /
   `send` / `outcome`, the tmux cockpit with the gate pane. Claude room,
   today's wall. kuggis PRs from kuggis.exe.xyz; I read them.
2. **The OS wall.** pf rule on the uid, the proxy, `HTTPS_PROXY` in the
   launcher, the network half of the check. The fetch hook becomes a second
   layer.
3. **Web through the door.** `search`, `fetch` with the remembered-URL rule,
   `kuggis url`. Claude's WebFetch comes off the tool list; its server-side
   WebSearch may stay, since the query goes to Anthropic.
4. **Other agents.** Codex and pi launchers, `--agent`, check green for each.
5. **The vault.** BigBrain's door in a release; one entry in `mcp.json`; the
   check confirms the room reaches that port and nothing else local.
6. **Onboard bigbrain-dev**, then retire `kuggis web`, `kuggis prs` and the
   Thinker's reviews. (Retired first, in the same PR: with merges in-cell the
   PR screen had no job left. Onboarding is blocked on a decision: the
   version-2 contract requires a development fork distinct from the upstream
   repo, and elsehow/BigBrain is both. Either fork it, or relax the rule.)
