# Cells

Status: plan, 2026-10-15. Nothing here is built yet.

kuggis today keeps a session's state in about ten places: tmux sessions,
`~/.box/state/*`, `~/.box/needs/*`, `thinking/*.pid|.jsonl|.head|.empty|.sent`,
review front matter, `dispatch.log` and whatever `gh` says. Every view
reassembles it, and most recent bugs came from that (#9, #13, the detached
review reading a half-written script). And every PR a VM writes waits for a
human review, which is the part that makes the whole thing a chore.

This plan replaces both: a typed process model with one event log, and
**cells**, so agents merge their own work and you are asked only where
something crosses a wall.

## Words

- **Place**: a VM, a macOS user, a repo, a set of keys. A place belongs to
  exactly one cell.
- **Cell**: places at one trust level. **Anything in a cell can reach
  everything in it**: agents merge their own code, and merged code runs
  everywhere in the cell. Separation inside a cell (other OS users, other
  keys) guards against accidents, never against the cell itself.
- **Sees / reaches**: the data a cell can read; where it can send data or
  spend money.
- **Door**: the only way anything crosses a cell's wall. See below.
- **kuggis**: defines the cells, builds their walls, carries everything
  between them and runs the dashboard. It is not a cell. It runs as your
  login user on the laptop, is developed on kuggis.exe.xyz, and is the one
  repo whose diffs you still read.

The rule that falls out: **two places that need different reach are two
cells.**

## The cells

| Cell | Holds | Sees | Reaches | Code comes in by |
|---|---|---|---|---|
| trusted | BigBrain and the vault, household data and its connectors, merrillfront's real runs, the Thinker | everything private | only your own accounts | releases, on conditional rules |
| forecasting | elsehow/airo, elsehow/agent-box, airo-dev, xrisk | public | capped keys, the airo site | merging when green |
| merrillfront-dev | the clean merrillfront and ibkr-transition repos, merrillfront-dev | invented households | its repos | merging when green |
| bigbrain-dev | elsehow/BigBrain, bigbrain-dev | public, scratch vaults | its repo | merging when green |
| bigbrain-others | testers' machines, bigbrain-family, bigbrain-shared, bigbrain.cool | other people's vaults | the hosts the app needs | a release you let through |
| hiring | fri-hiring | applicants | its own tables, capped keys | laptop sessions (no dev cell yet) |

Your login user stays outside every cell. It holds prod ssh, GitHub admin,
the signing keys and the exe.dev account; it's where kuggis runs.

### trusted

Everything private already flows together: projections end up in BigBrain,
and the Thinker reads BigBrain. Splitting household data from the vault buys
nothing, so they share a cell. Because anything in a cell reaches everything
in it, every release that enters gets the cell's whole reach. So trusted
constrains its reach, not its code:

1. **Its own macOS user(s), never your login.** If BigBrain runs as you, a
   release can write your shell rc, LaunchAgents and git hooks, which then
   run outside any allowlist with your keys.
2. **It reaches only accounts that are yours.** Each allowed host passes one
   test: only you can read what's sent there. The model API, your own mail
   over IMAP (no SMTP), the meeting-notes service, the household data
   connectors (read-only where they allow it), the update feed. No open web,
   except the Thinker's guarded fetch.

With both, a bad release can corrupt but can't leak. Backups and validation
cover corruption, so releases come in on conditional rules instead of your
review. The merrillfront study box joins trusted only if its egress is locked
to the same list; otherwise studies run on the laptop.

## Doors

A door carries one kind of thing. Its rule lives outside the cell (a
root-owned script that kuggis manages), so the cell can't merge it away.
What crosses has a type, so checks can run without you. Every crossing is
logged.

Rules come in three kinds:

- **open**: passes on its own.
- **conditional**: passes on its own unless a `hold_if` holds it.
- **yours**: waits for you.

Every `yours` door is a standing cost. The aim is to turn each into a
conditional one with a condition you trust.

| Kind | Door | Rule |
|---|---|---|
| code in | BigBrain release → trusted | open |
| | merrillfront release → trusted | conditional: private validation passes; held if the live recommendation changes |
| | BigBrain release → bigbrain-others | yours, after N days in trusted, with a model review of the release diff |
| words in | Thinker brief → any cell | yours, after a leak check for private facts |
| data in | laptop → a cell's inbox | open, one-way |
| numbers back | bench in trusted → bigbrain-dev | open; the type admits metric names and numbers only |
| repros back | failure in trusted → Thinker → synthetic brief → dev cell | yours; a raw failure or log never crosses |
| out | forecasting → airo site | conditional: held when the instrument version changes |
| | forecasting → ForecastBench upload, PRs to forecastingresearch/airo | yours |
| events | every cell → kuggis | open; checked against the schema, shown as text |

Two to watch. **Back** is the leakiest: a run cell's errors carry its data,
and it's the door most likely to be widened "just this once" while debugging.
**Words in** runs downhill: the Thinker sees more than any cell, so a brief is
how private facts would reach a public repo.

Adding or changing a door is a kuggis change, reviewed. A cell can't open its
own door.

## How things cross

Cells never talk to each other, and no cell holds a credential for another
cell's places. Each cell has an outbox and an inbox; kuggis carries:

1. take an item from the source cell's outbox
2. check it against its type
3. apply the door's rule: pass, hold, or wait for you
4. write it into the destination cell's inbox
5. log the item's hash, the outcome and who let it through

Three pieces exist already: `kuggis put` (data in), `session.sh deliver`
(a brief into a session) and the Thinker's outbox. Code shared between cells
moves as pinned releases, never as a live checkout.

**Builds run code** (`build.rs`, install scripts, Tauri hooks), so the builder
sits at the dev cell's trust level. Linux builds happen in the dev cell or a
throwaway VM; BigBrain's macOS build runs as its own laptop user that can't
read the signing key. kuggis signs only the finished bundle's hash. The
signature means "built from commit X", not "safe"; safety comes from the
destination's walls. If a build could read the signing key, it could sign
anything and ship it to testers through the update feed.

kuggis is the only thing that touches two cells, which makes it the most
trusted component. It stays small and reviewed.

## Cell definitions

Each cell is one file, checked against a schema that lives in this repo. This
repo is public, so the files themselves live in private config
(`~/.config/kuggis/cells/<cell>.yaml`, under version control there). The
dashboard shows a cell's file read-only, at the commit it's enforced from;
changing it is a reviewed change, never a settings screen.

```yaml
cell: forecasting
sees: public
places:
  airo-dev: { vm: airo-dev.exe.xyz, role: workers, keys: dev }
  xrisk:    { vm: xrisk.exe.xyz,    role: runner,  keys: run }
  repos:    [elsehow/airo, elsehow/agent-box]
keys:                        # USD a month, capped at the provider
  dev: { anthropic: <cap>, openai: <cap> }
  run: { anthropic: <cap>, openai: <cap>, gemini: <cap>, xai: <cap>, tavily: <cap> }
merge: when-green
deploy: last-good-head       # a head that passed tests and a stub run
doors:
  publish:
    out: airo.forecastingresearch.org
    via: /opt/kuggis/doors/publish     # root-owned, on xrisk
    rule: auto
    hold_if: instrument-changed
  forecastbench: { out: ForecastBench upload,           rule: yours }
  upstream:      { out: PRs to forecastingresearch/airo, rule: yours }
  data:          { in: laptop, carries: files, rule: open, one_way: true }
  briefs:        { in: thinker, rule: yours, check: leak }
  ntfy:          { out: ntfy, rule: open }
```

## The process model

One typed state machine per thing, folded from one event log:

```ts
type Brief  = proposed | approved | edited | declined
type Job    = starting | working
            | needs_you{why: question | permission | blocked | done, ask}
            | closed                                   // one session + worktree
type PR     = open{head} | reviewing{head} | reviewed{verdict, head}
            | merged | abandoned
type Think  = queued | running | produced(Brief | Review) | failed
type Run    = scheduled | running | failed | held{door, why} | published
type Release = built{commit, hash} | signed | held{door, why} | installed{cell}
```

- **Sources**: each VM appends typed lines to `~/.box/events.jsonl`. `hook.sh`
  and `needs-you` already fire at the right moments; they write events
  instead of state files. The Thinker's outbox and the door scripts emit
  events too.
- **Transport**: VMs can't reach the laptop and shouldn't. `kuggisd` keeps
  one ssh per VM tailing its log, so events arrive as they happen without
  opening a way into the laptop.
- **Validation**: every line is checked against the schema on the laptop;
  unknown shapes are dropped and logged. Free text inside an event is shown
  as text, which retires `room_text` as a patch.
- **The dashboard reads the fold.** Nothing else derives state. The state
  files above, the `thinking/` markers and the fzf home go.

"Needs you" keeps #17's meaning: a session can't go on without you (a
permission prompt, a question, blocked, or done), never "a run is ongoing".

## The dashboard

One page, organized by cell, in a fixed order that never re-sorts.

- Each cell is a heading with one line of state on the right.
- Under it, its sessions. A red dot means it needs you; otherwise its state
  is muted. Clicking a session copies `kuggis <cell> <session>`.
- A door holding something is a row in its cell like a session. Clicking it
  copies the command that opens the decision in your terminal
  (`kuggis publish forecasting`, `kuggis promote merrillfront`,
  `kuggis release bigbrain-others`).
- The Thinker is a session in trusted. Its red dot means a brief is waiting;
  `kuggis think` is where you dispatch it.
- Clicking a cell's name shows its definition file, read-only.
- No explanatory copy on the page. Red means "needs you" and nothing else.

## Order of work

1. **Schema and cell files.** Write the schema, then forecasting's file. The
   current `kuggis web` shows cells and their definitions.
2. **Event log.** `hook.sh` and `needs-you` append typed events; `kuggisd`
   tails and folds; the page reads the fold. Delete the state files, the
   `thinking/` markers and the fzf home.
3. **forecasting cell.**
   - elsehow/airo and elsehow/agent-box: drop the required approval; require
     CI (GitHub Actions, no secrets) and a model review posted as a status
     check, since the exe.dev bot can't approve its own PR. Fix the test that
     fails on airo's `main` first, so green means something.
   - Capped keys per cell; keys off the VMs if exe.dev's LLM integration
     covers every provider.
   - xrisk: archive what isn't airo or agent-box; it becomes the runner. Each
     run takes the last head that passed tests and a stub run, otherwise the
     previous one, and pages.
   - Results go to a branch that can't be force-pushed or deleted.
   - The publish door script, root-owned on xrisk. airo pins agent-box.
4. **Carrier and builder.** Outboxes and inboxes, root-owned door scripts, a
   builder user that can't read the signing key.
5. **trusted.** BigBrain moves to its own macOS user that owns the vault (a
   change to how the desktop app installs). A per-app egress allowlist
   enforced by the OS. Household connectors and merrillfront's real runs move
   in. The Thinker is already its own user; it joins the cell as a place.
6. **merrillfront-dev.** merrillfront's own isolated-development plan (in its
   private repo) supplies most of this: clean repo, synthetic fixtures, gates
   without household data, promotion and rollback. merrillfront-dev.exe.xyz
   exists but isn't tagged or in kuggis's project map yet.
7. **bigbrain-dev and bigbrain-others.** Merge when green on elsehow/BigBrain;
   the release door to testers.
8. **hiring.** A dev cell with invented applications, later.
