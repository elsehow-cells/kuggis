# Cells

Status: plan, 2026-10-15; rewritten 2026-10-16. Nothing here is built yet.

kuggis keeps a session's state in about ten places: tmux sessions,
`~/.box/state/*`, `~/.box/needs/*`, `thinking/*.pid|.jsonl|.head|.empty|.sent`,
review front matter, `dispatch.log` and whatever `gh` says. Every view
reassembles it, and most recent bugs came from that (#9, #13, the detached
review reading a half-written script). Meanwhile every PR a VM writes waits for
a human review — the part that makes the whole thing a chore.

This plan fixes both at once, because they share a cause. Reassemble state from
one event log, and merge becomes safe enough to automate — once you can say
precisely what a merged commit is allowed to reach.

## Words

- **Place**: a VM, a macOS user, a repo, a set of keys. A place belongs to
  exactly one cell.
- **Cell**: places at one trust level. **Anything in a cell can reach
  everything in it** — agents merge their own code, and merged code runs
  everywhere in the cell. Separation inside a cell (other OS users, other keys)
  guards against accidents, never against the cell itself.
- **Sees / reaches**: the data a cell can read; where it can send data or spend
  money.
- **Door**: the only way anything crosses a cell's wall. See below.
- **kuggis**: defines the cells, builds their walls, carries everything between
  them, runs the dashboard. It is not a cell. It runs as the login user on the
  laptop, is developed on kuggis.exe.xyz, and is the one repo whose diffs I
  still read myself.

The rule that falls out: **two places that need different reach are two
cells.**

## Threat model

Every door rule below should trace back to a line here; where it doesn't,
that's a gap. In scope: a compromised release, a prompt-injected agent, a
hostile dependency, the model going off-script, an agent widening its own
access. Out of scope: root on the laptop, a kernel exploit, someone reading
the screen, physical access. The walls are against processes I run myself under
control of code I can't fully review — not against a determined intruder who
already owns the laptop.

The login user stays outside every cell. It holds prod ssh, GitHub admin, the
signing keys and the exe.dev account; kuggis runs there. That's a lot of reach
for one cell that's also where Claude Code sessions still run — the honest
end-state needs deciding (see Open), because today trusted's wall rests partly
on an account that sits outside all cells with full reach.

### trusted

Everything private already flows together: projections end up in BigBrain, and
the Thinker reads BigBrain. Splitting household data from the vault buys
nothing, so they share a cell. Because anything in a cell reaches everything in
it, every release that enters gets the cell's whole reach — so trusted
constrains its reach, not its code:

1. **Its own macOS user(s), never the login user.** If BigBrain runs as me, a
   release can write my shell rc, LaunchAgents and git hooks, which then run
   outside any allowlist with my keys.
2. **It reaches only accounts that are mine.** Each allowed host passes one
   test: only I can read what's sent there. The model API, my own mail over
   IMAP (no SMTP), the meeting-notes service, the household data connectors
   (read-only where they allow it), the update feed. No open web, except the
   Thinker's guarded fetch — which is trusted's loose thread, dealt with under
   "words in".

With both, a bad release can corrupt but can't leak. Backups and validation
cover corruption, so releases come in on conditional rules instead of my
review. The merrillfront study box joins trusted only if its egress is locked
to the same list; otherwise studies run on the laptop.

## Doors

A door carries one kind of thing. Its rule lives outside the cell (a
root-owned script that kuggis manages), so the cell can't merge it away. What
crosses has a type, so checks can run without me. Every crossing is logged.

Rules come in three kinds:

- **open**: passes on its own.
- **conditional**: passes on its own unless a `hold_if` holds it.
- **yours**: waits for me.

Every `yours` door is a standing cost, so each one carries a graduation
criterion: what evidence would justify making it conditional, over what history,
and who decides. The dashboard counts how long each `yours` door has been
blocking something; drift I can see is drift I fix.

| Kind | Door | Rule |
|---|---|---|
| code in | BigBrain release → trusted | open |
| | merrillfront release → trusted | conditional: private validation passes; held if the live recommendation changes |
| | BigBrain release → bigbrain-others | yours, after N days in trusted, with a model review of the release diff |
| words in | Thinker brief → any cell | conditional; briefs are typed slots, verified for conformance — see below |
| data in | laptop → a cell's inbox | open, one-way |
| numbers back | bench in trusted → bigbrain-dev | open; the type admits metric names and numbers only |
| repros back | failure in trusted → Thinker → synthetic brief → dev cell | conditional; carries a typed `Repro`, never a raw log |
| out | forecasting → airo site | conditional: held when the instrument version changes |
| | forecasting → ForecastBench upload, PRs to forecastingresearch/airo | yours |
| events | every cell → kuggis | open; checked against the schema, shown as text |

**Words in runs downhill**: the Thinker sees more than any cell, so a brief is
how private facts would reach a public repo. A model judging prose that
contains the vault puts too much trust in the model. Instead the Thinker writes
briefs against a template in which private facts can only live in typed fields
that never leave trusted — the brief is *constructed* so nothing private is
present, and the check verifies conformance rather than hunting for absence.
Same idea as the numbers-back door, extended to words. This is what makes
`words in` conditional instead of a standing gate on every Thinker output.

**Repros back is the leakiest door**, because a run cell's errors carry its
data and debugging pressure makes widening it "just this once" feel harmless —
and a door widened once isn't a wall. So the pressure release is designed in
from day one: a typed `Repro` (error class, failing input description, stack,
the guarded surface of the data) emitted by `hook.sh` from the start, which the
Thinker can work from. The mitigation is removing the demand for raw logs, not
forbidding them.

Adding or changing a door is a kuggis change, reviewed, and requires a fresh
boundary check (below). A cell can't open its own door.

## How things cross

Cells never talk to each other, and no cell holds a credential for another
cell's places. Each cell has an outbox and an inbox; kuggis carries:

1. take an item from the source cell's outbox
2. check it against its type
3. apply the door's rule: pass, hold, or wait for me
4. write it into the destination cell's inbox
5. log the item's hash, the outcome and who let it through

Delivery is at-least-once, keyed on the item hash, so a retried crossing is a
no-op. An item that fails validation three times goes to a dead-letter view,
not a silent drop. If a destination inbox is unwritable, the source outbox
fills; a full outbox shows up on the dashboard as needing me, because
backpressure must be visible or it becomes a crash.

Merges happen laptop-side, not on GitHub's behalf: a door script merges when
CI and the model-review status check are green. The exe.dev bot can't approve
its own PRs (verified in findings.md C4) and whether it can merge without
approvals is untested — so I don't depend on either. A merge is a logged
crossing, identical in every dev cell.

Three pieces exist already: `kuggis put` (data in), `session.sh deliver` (a
brief into a session) and the Thinker's outbox. Code shared between cells moves
as pinned releases, never as a live checkout.

**Builds run code** (`build.rs`, install scripts, Tauri hooks), so the builder
sits at the dev cell's trust level. Linux builds happen in the dev cell or a
throwaway VM; BigBrain's macOS build runs as its own laptop user that can't
read the signing key. kuggis signs only the finished bundle's hash. The
signature means "built from commit X", not "safe"; safety comes from the
destination's walls. If a build could read the signing key, it could sign
anything and ship it to testers through the update feed.

kuggis is the only thing that touches two cells, which makes it the most
trusted component — and the concentration risk, since this plan loads it with
the schema, the carrier, the fold, the dashboard, door management and signing.
So it gets a scope charter, reviewed like a door: kuggis never holds
per-provider keys (that's the exe.dev LLM integration's job or a proxy's), never
holds vault data, never runs the Thinker, never contains a cell itself.

## Cell definitions

Each cell is one file, checked against a schema that lives in this repo. This
repo is public, so the files themselves live in private config
(`~/.config/kuggis/cells/<cell>.yaml`, version-controlled there). Where that
version control lives needs deciding: a private GitHub repo puts GitHub inside
the walls; a local-only repo needs an offsite backup story, or cell definitions
are unrecoverable. The dashboard shows a cell's file read-only, at the commit
it's enforced from; changing it is a reviewed change, never a settings screen.

```yaml
cell: forecasting
sees: public
places:
  airo-dev: { vm: airo-dev.exe.xyz, role: workers, keys: dev }
  xrisk:    { vm: xrisk.exe.xyz,    role: runner,  keys: run }
  repos:    [elsehow/airo, elsehow/agent-box]
keys:                        # USD a month, capped at the provider
  dev: { anthropic: <cap>, openai: <cap> }
  run: { anthropic: <cap>, openai: <cap>, gemini: <cap>, xai: <cap>, tavily: <cap> }
merge: when-green
deploy: last-good-head       # a head that passed tests and a stub run
doors:
  publish:
    out: airo.forecastingresearch.org
    via: /opt/kuggis/doors/publish     # root-owned, on xrisk
    rule: auto
    hold_if: instrument-changed
  forecastbench: { out: ForecastBench upload,           rule: yours }
  upstream:      { out: PRs to forecastingresearch/airo, rule: yours }
  data:          { in: laptop, carries: files, rule: open, one_way: true }
  briefs:        { in: thinker, rule: conditional, check: conformance }
  ntfy:          { out: ntfy, rule: open }
```

A `<cap>` that a provider won't enforce is worse than none: it *reads* safe.
Anthropic and OpenAI enforce key budgets; Gemini, xAI and tavily need checking,
and where they can't cap, the key routes through a proxy that enforces the cap
or stays out of the cell.

## The process model

One typed state machine per thing, folded from one event log:

```ts
type Brief  = proposed | approved | edited | declined
type Job    = starting | working
            | needs_you{why: question | permission | blocked | done, ask}
            | closed                                   // one session + worktree
type PR     = open{head} | reviewing{head} | reviewed{verdict, head}
            | merged | abandoned
type Think  = queued | running | produced(Brief | Review) | failed
type Run    = scheduled | running | failed | held{door, why} | published
type Release = built{commit, hash} | signed | held{door, why} | installed{cell}
```

"Thing" needs a definition, and it isn't "tmux session name". Sessions are
recreated, worktrees reattach, VMs rebuild. Every event therefore carries:

- a `session_id`, minted at creation and carried in `BOX_*`, surviving tmux
  recreation and worktree reattachment;
- a per-VM monotonic sequence number, so the fold is orderable without trusting
  arrival order or clocks;
- a schema version, so lines from stale `hook.sh`s validate or get rejected by
  rule instead of by surprise.

- **Sources**: each VM appends typed lines to `~/.box/events.jsonl`. `hook.sh`
  and `needs-you` already fire at the right moments; they write events instead
  of state files. The Thinker's outbox and the door scripts emit events too.
- **Transport**: VMs can't reach the laptop and shouldn't. `kuggisd` keeps one
  ssh per VM tailing its log, so events arrive as they happen without opening a
  way into the laptop.
- **Validation**: every line is checked against the schema on the laptop;
  unknown shapes are dropped and logged. Free text inside an event is shown as
  text, which retires `room_text` as a patch.
- **The dashboard reads the fold.** Nothing else derives state.

"Needs you" keeps #17's meaning: a session can't go on without me (a permission
prompt, a question, blocked, or done), never "a run is ongoing".

## Boundary checks

findings.md did this for the kuggis VM; each cell gets the same treatment, run
by `kuggis audit <cell>` and re-run whenever a door changes: can the dev VM
reach the other VMs; does the door script refuse an oversized or mis-typed
item; can a cell read its own door script; what does egress actually allow
(allowlists fail open unless tested); does a crossing actually leave a log
line. A cell stays in until it passes.

## When something goes wrong

Incidents are when door widening happens, so the alternative exists before the
incident: `kuggis seal <cell>` holds every door out of the cell in one action
and freezes anything it feeds (the update feed, publishes). The dashboard shows
a sealed cell plainly. Unsealing is a reviewed change.

## The dashboard

One page, organized by cell, in a fixed order that never re-sorts.

- Each cell is a heading with one line of state on the right.
- Under it, its sessions. A red dot means it needs me; otherwise its state is
  muted. Clicking a session copies `kuggis <cell> <session>`.
- A door holding something is a row in its cell like a session, with how long
  it's been holding. Clicking it copies the command that opens the decision
  (`kuggis publish forecasting`, `kuggis promote merrillfront`,
  `kuggis release bigbrain-others`).
- The Thinker is a session in trusted. Its red dot means a brief is waiting;
  `kuggis think` is where I dispatch it.
- Clicking a cell's name shows its definition file, read-only.
- No explanatory copy on the page. Red means "needs you" and nothing else.

## Order of work

1. **Schema, identities and cell files.** Write the schema with the identity
   fields above, then forecasting's file. The current `kuggis web` shows cells
   and their definitions.
2. **Event log, in shadow mode.** `hook.sh` and `needs-you` append typed
   events; `kuggisd` tails and folds. Nothing is deleted for one to two weeks:
   the derived state diffs against the existing state files, alerting on
   divergence. Then state files retire one type at a time, starting with what
   the fold demonstrably reproduces — the `thinking/` markers, the fzf home,
   the rest. Bugs #9 and #13 were state-assembly bugs, so the fold has to be
   proven before the migration, not alongside it.
3. **forecasting cell.**
   - elsehow/airo and elsehow/agent-box: drop the required approval; require
     CI (GitHub Actions, no secrets) and a model review posted as a status
     check; the laptop-side merge door takes it from there. Fix the test that
     fails on airo's `main` first, so green means something.
   - Capped keys per cell (verified enforceable, see above); keys off the VMs
     if exe.dev's LLM integration covers every provider.
   - xrisk: archive what isn't airo or agent-box; it becomes the runner. Each
     run takes the last head that passed tests and a stub run, otherwise the
     previous one, and pages.
   - Results go to a branch that can't be force-pushed or deleted.
   - The publish door script, root-owned on xrisk. airo pins agent-box.
4. **Carrier and builder.** Outboxes and inboxes with the delivery semantics
   above, root-owned door scripts, a builder user that can't read the signing
   key, the `Repro` type, `kuggis audit`, `kuggis seal`.
5. **trusted.** BigBrain moves to its own macOS user that owns the vault (a
   change to how the desktop app installs). A per-app egress allowlist enforced
   by the OS. Household connectors and merrillfront's real runs move in. The
   Thinker is already its own user; it joins the cell as a place. Briefs move
   to the typed-slot format so `words in` can be conditional.
6. **merrillfront-dev.** merrillfront's own isolated-development plan (in its
   private repo) supplies most of this: clean repo, synthetic fixtures, gates
   without household data, promotion and rollback. merrillfront-dev.exe.xyz
   exists but isn't tagged or in kuggis's project map yet.
7. **bigbrain-dev and bigbrain-others.** Merge when green on elsehow/BigBrain;
   the release door to testers with its graduation criterion written down.
8. **hiring.** A dev cell with invented applications, later.

## Open

- Monthly caps per cell and per key, and which providers can actually enforce
  them.
- airo's publish rule: recommended auto, held when the instrument changes — the
  `hold_if` needs a typed event carrying the instrument's hash, so the door's
  condition depends on event fidelity, not log parsing.
- Whether exe.dev's LLM integration can hold every provider's key, and cap it.
- Where the private cell YAMLs are version-controlled.
- The end-state for laptop sessions: they run as the login user, outside every
  cell, seeing and reaching everything, shrinking over time to operating doors.
  Either Claude Code moves into cells and the login user becomes a pure
  operator place, or the login user's door policy to trusted has to be written
  down — prod ssh and GitHub admin is a lot of reach to leave implicit.
- The BigBrain plugin runs inside laptop Claude Code sessions as the login
  user; it should talk to trusted's API and hold no vault data itself.
- The study box's egress, or moving studies to the laptop.
